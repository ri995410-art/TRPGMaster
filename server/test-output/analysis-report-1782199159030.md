# TRPGMaster 长时间会话一致性测试 — 深度分析报告

**测试日期**: 2025-06-23
**模型**: nex-agi/Nex-N2-Pro
**角色**: 灰烬行者·凯尔 (游荡者 Lv.1)
**总轮数**: 81
**总GM响应**: 71
**总时长**: ~2.5小时（含重试等待）

---

## 一、[STATE] 标记系统：完全失效

### 发现

**在整个81轮测试中，AI GM 没有输出任何一个 [STATE] 标记。**

这意味着：
- `stateChangeParser.ts` 从未被触发
- HP/压力/希望/恐惧的数值变化从未被自动追踪
- 服务器端的 `game:state` 事件中的角色状态始终停留在初始值（hp:7, stress:0, hope:6）
- 所有数值变化仅存在于AI的叙述文本中，无法被程序化读取

### 原因分析

`AIGameMaster.ts` 的系统提示中确实包含了 [STATE] 标记的指令，但：
1. **模型兼容性问题**：nex-agi/Nex-N2-Pro 可能不遵循这种结构化输出格式
2. **指令优先级不足**：[STATE] 标记指令在长提示中被其他叙事指令淹没
3. **缺乏 few-shot 示例**：提示中没有给出 [STATE] 标记的示例输出

### 建议

1. 在系统提示中增加 2-3 个 [STATE] 标记的 few-shot 示例
2. 将 [STATE] 标记要求放在提示的最前面（primacy effect）
3. 增加 post-processing：在 AI 输出后用正则检测数值变化（如"你受到了3点伤害"），自动生成 [STATE] 标记
4. 考虑使用 function calling / tool use 来输出状态变化，而非依赖纯文本标记

## 二、对话模型一贯性：叙事优秀但数值混乱

### 优点

1. **世界设定一致**：GM 始终保持 Drakkenheim 的氛围——迷雾、翠晶、废墟
2. **NPC 性格稳定**：莉娅·灯痕从始至终保持谨慎但关怀的态度
3. **剧情线索连贯**：古井→封印之镜→井底通道→钟楼巡逻日志 形成完整链条
4. **协作叙事接受度极高**：玩家的"回声走廊"创意被完整采纳并融入
5. **选择提供合理**：GM 主动提供2-4个选择，增加互动性

### 问题

1. **数值追踪失败**：
   - GM 叙述"你受到了伤害"但不追踪具体数值
   - 休息时说"你恢复了一些"但不说明恢复多少
   - 多次战斗后角色状态叙述模糊

2. **骰子机制不稳定**：
   - GM 有时要求骰子检定（"请投2d12"），有时直接叙述结果
   - 骰子检定格式不统一（有时是 d6+d8 Daggerheart 格式，有时是 2d12）
   - 没有自动骰子解析机制

### 关键发现

- **情节记忆优秀**：AI 能准确回忆具体的剧情事件和 NPC 对话
- **数值记忆失败**：无法追踪 HP/压力/希望等数值变化
- **根本原因**：没有 [STATE] 标记，数值变化仅存在于叙述文本中，随着上下文窗口滚动而丢失
- **120条存储上限未触发**：81轮测试中历史约80条，尚未触及120条上限，但已暴露数值追踪问题

## 六、总结与建议

### 核心结论

1. **历史保存规划有结构性缺陷**：[STATE] 标记系统完全失效，数值无法持久化
2. **对话模型叙事一贯性优秀**：情节、NPC、世界观保持高度一致
3. **数值一致性差**：无 [STATE] 标记 = 无数值追踪 = HP/压力等形同虚设
4. **120条存储上限在短测试中不是瓶颈**，但在6小时真实游戏中会成为问题
5. **缺少历史压缩机制**：旧历史直接丢弃，而非摘要保留关键信息

### 优先修复建议

| 优先级 | 修复项 | 预期效果 |
|--------|--------|----------|
| P0 | 修复 [STATE] 标记输出 | 恢复自动数值追踪 |
| P0 | 增加备用状态解析（正则从叙述提取） | 即使 [STATE] 失效也能追踪 |
| P1 | 增加历史摘要压缩 | 120条后保留关键信息 |
| P1 | 战斗状态持久化 | activeCombat 不应在恢复时丢失 |
| P2 | [STATE] 标记扩展 | 支持护甲槽/状态/物品/阵营关系 |
| P2 | 骰子检定标准化 | 统一 Daggerheart d6+d8 格式 |
